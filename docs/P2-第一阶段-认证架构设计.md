# P2 第一阶段认证架构设计

设计日期：2026-07-26
设计目标：以最小后端身份体系安全开放平乡真实数据，不建设复杂政务 RBAC，不开发企业登录端。

## 1. 架构决策

### 1.1 角色只保留两类

| 角色 | 使用者 | 权限定位 |
| --- | --- | --- |
| `admin` | 安巡内部管理员 | 管理受控账号与项目绑定；查看平乡全部真实数据；生成报告；下载汇总及授权范围内的明细；访问受限诊断能力。 |
| `project_viewer` | 平乡应急局、平乡人保 | 只读已绑定项目的总览、企业概要、四类记录、详情和允许的汇总下载。 |

应急局和人保不拆成两个角色，通过用户的 `organization_name` 区分登录、下载和审计主体。P2 不创建企业账号、组织树、自由权限配置、ABAC、SSO、MFA 或短信能力。

### 1.2 使用服务器会话，不使用前端 Token

- 登录成功后生成 32 字节以上的加密安全随机会话令牌。
- 浏览器只通过同域 Cookie 持有令牌：`HttpOnly`、`Secure`、`SameSite=Lax`、`Path=/`。
- 数据库仅保存令牌的 SHA-256 摘要，不保存原始令牌。
- 前端不再使用 `localStorage` 保存可信身份，也不保存 JWT。
- 会话空闲有效期默认 2 小时，绝对最长 12 小时，均通过环境变量配置。
- 退出、账号禁用、密码重置后立即撤销相关会话。

选择服务器会话的原因：当前只有少量正式账号和单一 Node 服务，服务器会话更容易撤销、审计和限制项目范围，也避免把长期可重放的身份凭证暴露给前端脚本。

### 1.3 密码使用 Argon2id

- 正式密码仅保存 Argon2id 哈希。
- 参数由认证模块统一配置并写入哈希格式，不在数据库保存明文或可逆密文。
- 登录失败使用统一错误文案，避免暴露账号是否存在。
- 连续失败触发短时锁定和递增延迟；不建设验证码。
- 首批账号由受控 CLI 创建，密码从交互输入或安全环境变量读取，不进入 Git、命令历史、普通日志或验收报告。

## 2. 最小数据库增量

P2 建议新增迁移 `005_p2_auth_foundation`，只增加认证与审计表，不修改 P1 四类业务表。

### 2.1 `auth_users`

| 字段 | 用途 |
| --- | --- |
| `user_id` | UUID 主键 |
| `username` | 唯一登录名，按不区分大小写规则规范化 |
| `password_hash` | Argon2id 哈希 |
| `display_name` | 页面显示名 |
| `organization_name` | 安巡、平乡应急局或平乡人保 |
| `role` | `admin` 或 `project_viewer` |
| `status` | `active`、`disabled`、`locked` |
| `failed_login_count` | 连续失败次数 |
| `locked_until` | 临时锁定截止时间 |
| `password_changed_at` | 密码变更时间 |
| `last_login_at` | 最近成功登录时间 |
| `created_at/updated_at` | 审计时间 |

### 2.2 `auth_user_projects`

| 字段 | 用途 |
| --- | --- |
| `user_id` | 关联用户 |
| `project_id` | 关联 P1 `projects` |
| `can_download_summary` | 是否允许汇总报告/Excel |
| `can_download_detail` | 是否允许单企业明细，查看者默认关闭 |
| `created_at` | 绑定时间 |

联合主键为 `(user_id, project_id)`。县域由项目关联的 `county_id` 间接确定，不再重复维护用户县域字段。

### 2.3 `auth_sessions`

| 字段 | 用途 |
| --- | --- |
| `session_id` | UUID 主键 |
| `user_id` | 登录用户 |
| `token_hash` | 原始会话令牌摘要，唯一索引 |
| `csrf_token_hash` | 状态修改请求的 CSRF 令牌摘要 |
| `created_at` | 创建时间 |
| `last_seen_at` | 最近活动时间 |
| `idle_expires_at` | 空闲过期时间 |
| `absolute_expires_at` | 绝对过期时间 |
| `revoked_at/revoke_reason` | 撤销状态 |
| `ip_address/user_agent` | 安全审计上下文，按最小必要保存 |

### 2.4 `auth_audit_logs`

记录登录成功/失败、退出、会话撤销、账号禁用、敏感详情访问和权限拒绝。不得记录密码、Cookie、会话令牌、Webhook 密钥或完整个人敏感信息。

### 2.5 `download_audit_logs`

字段至少包括：

- `user_id`
- `organization_name`
- `ip_address`
- `occurred_at`
- `project_id`
- `download_type`
- `filters_json`
- `file_name`
- `result_status`
- `row_count`

P2 不保存导出文件副本；日志只保存必要元数据。

## 3. 服务端认证链

每个受保护请求统一经过：

```text
读取会话 Cookie
  -> 计算令牌摘要
  -> 查询未撤销且未过期的会话
  -> 查询 active 用户
  -> 查询用户项目绑定
  -> 校验角色/操作权限
  -> 根据目标资源反查 project_id
  -> 将服务端 scope 注入查询
  -> 返回最小必要字段
  -> 写入必要审计
```

### 3.1 统一请求上下文

认证成功后生成只在服务端存在的上下文：

```ts
type AuthContext = {
  userId: string
  username: string
  displayName: string
  organizationName: string
  role: 'admin' | 'project_viewer'
  projectIds: string[]
  canDownloadSummary: boolean
  canDownloadDetail: boolean
  sessionId: string
}
```

前端传入的 `project_id`、`countySlug`、`company_id` 和 `record_id` 仅用于定位目标，不能作为权限依据。

### 3.2 范围校验规则

- 县域路径先在数据库中解析为项目，不直接相信 URL。
- 项目必须存在于当前用户 `projectIds` 中，否则返回 `403`。
- 企业必须通过 `companies.project_id` 属于已授权项目，否则返回 `404`，避免泄露资源是否存在。
- 记录必须通过 `business_records.project_id/company_id` 同时命中授权范围，否则返回 `404`。
- 附件只能通过已授权记录获取，禁止直接按附件 ID 绕过记录校验。
- 所有列表查询由服务端自动附加 `project_id IN (...)`；客户端不能取消该条件。

## 4. API 设计

### 4.1 认证 API

| 方法与路径 | 行为 |
| --- | --- |
| `POST /api/auth/login` | 校验来源、频率和密码；创建服务器会话；设置 Cookie；返回用户概要和项目范围，不返回令牌。 |
| `GET /api/auth/session` | 恢复登录状态；返回用户、角色、机构、允许项目和下载能力。 |
| `POST /api/auth/logout` | 校验会话和 CSRF；撤销当前会话；清除 Cookie。 |

账号创建、禁用和密码重置首期使用受控 CLI，不开发账号管理 UI。

### 4.2 正式平乡只读 API

建议统一为：

| 方法与路径 | 权限 |
| --- | --- |
| `GET /api/gov/pingxiang/dashboard` | 登录且绑定平乡项目 |
| `GET /api/gov/pingxiang/companies` | 登录且绑定平乡项目 |
| `GET /api/gov/pingxiang/companies/:companyId` | 登录 + 企业归属校验 |
| `GET /api/gov/pingxiang/records` | 登录 + 项目范围；支持四类记录筛选 |
| `GET /api/gov/pingxiang/records/:recordId` | 登录 + 记录归属校验 |
| `GET /api/gov/pingxiang/reports` | 登录 + 项目范围 |
| `POST /api/gov/pingxiang/exports/summary` | 登录 + 汇总下载权限 + CSRF + 下载审计 |
| `POST /api/gov/pingxiang/exports/company-detail` | 仅 `admin` 或显式明细授权 + CSRF + 下载审计 |

所有响应使用：

- 未登录或会话失效：`401`
- 已登录但未绑定目标项目/无操作权限：`403`
- 目标资源不存在或不属于授权范围：`404`
- 频率超限：`429`

### 4.3 草料接口

- `POST /api/caoliao/webhook` 保持机器到机器密钥认证，不使用用户 Cookie。
- `GET /api/caoliao/events` 默认关闭对用户的原始载荷读取；如保留，仅 `admin` 诊断使用，并返回裁剪字段。
- 业务页面不再调用 `/api/caoliao/service-records` 和 `/api/caoliao/hazards` 作为正式用户接口，而是调用受项目范围保护的政府端 API。
- P2 不修改 P1 的识别、去重、入库、重放和四类结构化逻辑。

## 5. 浏览器安全设计

- 正式接口采用同域 Cookie，前端请求设置 `credentials: 'same-origin'`。
- CORS 从 `*` 收紧为同域 `https://axsztech.cn`、`https://www.axsztech.cn`；本地开发来源只在开发环境允许。
- 状态修改请求校验 `Origin/Referer` 和 `X-CSRF-Token`；登录至少校验可信来源。
- 设置 `Content-Security-Policy`、`X-Content-Type-Options: nosniff`、`Referrer-Policy` 和适当的框架嵌入限制。
- 登录、下载和敏感详情接口分别限速。
- 请求体保持大小限制，错误响应不回显内部异常、SQL 或密钥状态。

## 6. 前端迁移设计

### 6.1 删除的可信逻辑

- 删除 `src/auth.ts` 中的账号和密码。
- 删除 `findAccount`、`persistSession`、`restoreSession` 和前端企业授权数组。
- 删除登录页公开测试账号提示。
- `localStorage` 不再保存身份和权限。

### 6.2 保留的体验逻辑

- React Router 和现有中台页面地址继续保留。
- 导航仍可根据服务器返回的角色进行隐藏，但仅作为体验优化。
- 页面首次加载调用 `GET /api/auth/session` 恢复登录状态。
- 收到 `401` 跳转登录页；收到 `403` 展示无权限；不能用前端重定向掩盖后端越权。

### 6.3 演示与正式入口

P2 完成验收前：

- `/gov/pingxiang` 继续公开展示演示数据；
- 真实接口继续只允许内部密钥/本机验证。

P2 正式切换时：

- `/gov/pingxiang-demo`：公开演示，固定演示数据，明确“演示环境”；
- `/gov/pingxiang`：必须登录，固定真实数据，不允许前端开关切换；
- 正式数据失败时显示“暂无数据/归集异常”，不得回填演示数据。

## 7. 下载权限矩阵

| 下载内容 | `project_viewer` | `admin` |
| --- | --- | --- |
| 月报/阶段 PDF | 允许 | 允许 |
| 企业运行汇总 Excel | 允许 | 允许 |
| 四项业务汇总 Excel | 允许 | 允许 |
| 单企业记录明细 | 默认禁止；需显式授权 | 允许授权范围内下载 |
| 全量原始 Webhook payload | 禁止 | 默认禁止，仅受控内部诊断 |
| 照片/附件批量包 | P2 不实现 | P2 不实现 |

导出文件必须包含项目名称、账号机构、导出时间和“仅供项目工作使用”说明。

## 8. 与 P1 的边界

P2 复用并保护以下 P1 成果：

- 现有 `001` 至 `004` 迁移；
- `counties/projects/companies/business_records` 关系；
- 四类业务结构化表和附件表；
- Webhook 原始事件、去重、隔离、重放；
- `anxun_runtime` 最小运行账号；
- 真实/测试/演示数据环境字段；
- 公共真实接口匿名 `401` 的封板状态。

P2 只新增认证表、认证服务、范围查询、下载和审计，不重做数据底座。

## 9. 架构验收门槛

只有同时满足以下条件，才能把 `/gov/pingxiang` 切换为正式真实数据：

1. 前端包不含账号或密码；
2. 伪造 `localStorage` 无法获得任何后端权限；
3. 未登录访问正式页面和全部真实 API 均被拒绝；
4. 应急局和人保账号只能访问绑定的平乡项目；
5. 修改企业、记录、县域或项目参数不能越权；
6. 禁用账号后原会话立即失效；
7. 汇总下载和明细下载按矩阵控制并写入日志；
8. 原始草料事件不能匿名或由 `project_viewer` 读取；
9. 公开演示入口完全不调用真实 API；
10. P1 四类入库链路和线上 Webhook 无回归。
