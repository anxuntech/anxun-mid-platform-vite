# P2 第一阶段实施计划

计划日期：2026-07-26
计划基线：`p1-complete-20260726`
目标分支：`codex/p2-auth-rbac-production`

## 1. 实施原则

1. 先保护接口，再切换页面；正式真实数据绝不先于鉴权开放。
2. 只建设 `admin` 与 `project_viewer` 两类角色。
3. 应急局和人保用独立账号、同一只读角色，通过机构字段和日志区分。
4. 复用 P1 MySQL 数据底座和 `anxun_runtime`，不修改四类业务入库链路。
5. 每个阶段都必须可单独回退；迁移先备份，部署保留静态和服务端回退点。
6. P2 验收完成前，公共平乡页面保持演示环境，真实接口保持匿名 `401`。

## 2. 分阶段实施

### 阶段 A：认证数据底座

交付：

- 新增 `005_p2_auth_foundation.up.sql/down.sql`。
- 新增用户、用户项目绑定、服务器会话、认证审计和下载审计表。
- 增加索引、外键、状态约束和会话过期索引。
- 新增迁移结构测试和回退测试。

验收：

- `005` 可在空库和 P1 现有库上幂等执行；
- 回退仅删除 P2 新表，不影响 P1 数据；
- 无明文密码、会话令牌或密钥进入数据库迁移。

### 阶段 B：认证服务和受控账号 CLI

交付：

- Argon2id 密码模块；
- 会话创建、恢复、续期、撤销和禁用检查；
- `POST /api/auth/login`、`GET /api/auth/session`、`POST /api/auth/logout`；
- 登录频率限制、失败延迟和认证审计；
- 受控账号创建、禁用、密码重置、项目绑定 CLI。

验收：

- 正确登录、错误密码、锁定、禁用、退出、空闲过期和绝对过期测试通过；
- 数据库只保存密码哈希和会话摘要；
- 正式初始密码不出现在 Git、日志或报告。

### 阶段 C：统一授权与项目范围

交付：

- `authenticateSession` 统一认证；
- `requireRole/requireProjectAccess/requireDownloadPermission` 授权辅助层；
- 服务端 `AuthContext`；
- 查询仓库强制接收授权项目范围；
- 企业、记录和附件的反查校验。

验收：

- 未登录为 `401`；
- 未绑定项目为 `403`；
- 不属于范围的企业、记录和附件为 `404`；
- 修改 URL、`company_id`、`record_id`、`countySlug`、`project_id` 均不能越权。

### 阶段 D：政府端正式 API

交付：

- 将现有平乡聚合查询改为接受服务端授权的 `projectId`；
- 增加企业列表/详情、四类记录列表/详情和报告数据接口；
- 响应字段按角色裁剪和联系人脱敏；
- 保留内部自动化密钥通道，但与用户会话分离。

验收：

- 首页、列表、抽屉、三级详情和报告使用同一数据库口径；
- 与 P1 真实 RDS 抽样对账；
- `project_viewer` 无法访问原始 Webhook payload；
- P1 四类 Webhook 入库、去重、重放无回归。

### 阶段 E：前端正式登录和页面切换

交付：

- 前端登录改为调用后端；
- 删除明文测试账号和 `localStorage` 可信会话；
- 会话刷新恢复、退出和过期处理；
- 导航按服务器身份展示；
- `/gov/pingxiang-demo` 固定演示；
- `/gov/pingxiang` 在认证完成后固定真实数据。

验收：

- 静态包搜索不到测试账号和密码；
- 修改 `localStorage` 不产生权限；
- 刷新、前进、后退和直达地址保持正确；
- 演示接口与真实接口完全分离，真实失败不回填演示数字。

### 阶段 F：受控下载和审计

交付：

- 汇总 PDF/Excel 服务端导出；
- 单企业明细按权限导出；
- 下载前重新验证会话、项目和下载权限；
- 下载审计查询由 `admin` 受控使用；
- 文件加入项目、机构、导出时间和用途说明。

验收：

- 应急局、人保下载日志可区分机构和账号；
- `project_viewer` 不能下载原始载荷、附件包或未授权明细；
- 复制下载地址、修改筛选或直接调用接口不能绕过权限；
- 下载失败同样记录结果但不泄露内部错误。

### 阶段 G：安全基线、上线和回退

交付：

- 同域 Cookie、CSRF、来源校验、安全响应头、限速、请求体限制；
- 生产环境变量模板和权限检查；
- 三个初始账号的受控创建记录：安巡管理员、平乡应急局、平乡人保；
- 自动化越权测试、数据对账和回归报告；
- 数据库、服务端和静态文件回退材料。

上线顺序：

1. 创建数据库备份并记录 schema 版本；
2. 执行 `005` 迁移并验证；
3. 部署后端认证能力，但保持正式真实页面关闭；
4. 使用测试路径完成三个账号联调；
5. 完成越权、下载、禁用和审计验收；
6. 再启用正式 `/gov/pingxiang`；
7. 保留 `/gov/pingxiang-demo` 演示入口；
8. 验证官网、中台、Webhook、演示页和正式页。

回退顺序：

1. 立即关闭正式真实页面入口和用户真实数据 API；
2. 恢复上一版 Node 服务和前端静态文件；
3. 公共入口回到演示版，禁止把真实故障回填成演示数据；
4. 会话 Cookie 统一失效；
5. 只有在确认无 P2 会话/审计保留要求后才执行 `005` 回退；默认保留审计数据并停止使用新表。

## 4. 自动化测试清单

### 4.1 单元和服务端测试

- 密码哈希与校验；
- 会话摘要、过期、续期和撤销；
- 登录失败限速；
- 账号禁用；
- CSRF 和来源校验；
- 角色权限矩阵；
- 用户项目绑定；
- 企业/记录/附件归属；
- 汇总和明细下载权限；
- 日志脱敏。

### 4.2 越权矩阵

对安巡管理员、应急局、人保、未登录四类主体分别验证：

- 平乡总览；
- 企业列表和详情；
- 隐患、巡检、作业票、培训列表和详情；
- 报告；
- 汇总下载；
- 单企业明细；
- 原始 Webhook；
- 修改项目、县域、企业、记录和附件参数；
- 复用已退出或已禁用会话。

### 4.3 回归

- `npm ci`
- TypeScript 检查；
- `npm run build`
- 服务端测试；
- Playwright 路由和会话测试；
- Webhook 四类受控测试；
- 官网、中台、平乡演示页面；
- 公共真实 API 匿名拒绝；
- 浏览器控制台无认证、Cookie、CORS 和资源错误。

## 5. 第一阶段完成标准

本阶段只在以下成果全部形成后结束：

- 当前认证与数据隔离现状有代码证据；
- 角色、服务器会话、项目范围和下载权限设计明确；
- P1 复用边界和禁止修改范围明确；
- 数据库增量、接口、前端迁移、测试、上线和回退顺序明确；
- 未实施登录、迁移、真实页面切换或线上部署；
- 分支可供后续 P2 实施直接继续。

## 6. 第一阶段结论

当前架构适合按上述最小方案实施 P2，不需要重做 P1 数据库。下一实施动作应从 `005_p2_auth_foundation` 和服务端会话测试开始；在越权矩阵和下载审计完成前，不允许把平乡公共页面切换为真实数据。
