# P1 审计问题修复运行说明

## 时间口径

- 业务时间统一按 `Asia/Shanghai` 解释和展示。
- MySQL 会话时区统一为 `+08:00`。
- 带 `Z` 或时区偏移的时间先换算为北京时间。
- 不带时区的 `YYYY-MM-DD HH:mm:ss` 视为业务方填写的北京时间，不再受开发电脑、VPN出口或服务器系统时区影响。

## 历史 8 小时偏差校正

校正脚本默认只输出候选数量，不修改数据：

```bash
npm run db:repair:beijing-time -- --environment=test
```

正式执行前必须先完成 RDS 备份并记录备份编号，然后显式开启：

```bash
ALLOW_TIME_REPAIR=true \
TIME_REPAIR_BACKUP_ID="<已核验的RDS备份编号>" \
npm run db:repair:beijing-time -- --environment=test --apply
```

脚本仅选择 `created_at - received_at` 约等于 8 小时的事件，并在单个数据库事务中同步校正原始事件、业务记录和四类明细时间。公共演示页仍保持演示数据。

## 数据库迁移

`004_p1_data_contract` 增加以下字段：

- 无效 JSON 的原始正文与解析错误；
- 企业地址、联系人和联系电话；
- 来源连接器与项目的显式绑定，企业匹配和质量统计不再依赖连接器命名；
- 数据质量问题按事件和状态检索的索引。

数据库 DDL 在 MySQL 中会自动提交。迁移和回退脚本不再宣称事务可原子回滚，并使用数据库互斥锁避免并发执行。任何 DDL 失败后必须先检查实际表结构，再决定修复或重试。

## 四类链路验证

应用迁移并配置测试连接后执行：

```bash
npm run db:verify:four-types
```

该命令会真实写入隐患、巡检、作业票和培训考试各一条测试记录，核验四张明细表后自动清理本次测试数据。添加 `--keep` 才会保留验证记录。

## JSONL 断点续传

可限制迁移行号：

```bash
npm run db:import:jsonl -- --file=/path/file.jsonl --start-line=101 --end-line=200
```

可从原批次继续，已经成功的行会跳过，失败行会重试：

```bash
npm run db:import:jsonl -- --file=/path/file.jsonl --resume-batch=<batch-id>
```

无效 JSON 不再只写迁移日志，而是保留原始行并隔离为数据质量问题。

## 鉴权与日志

- Webhook 查询参数密钥默认关闭，优先使用请求头。
- 只有草料端确实无法设置请求头时，才临时设置 `WEBHOOK_ALLOW_QUERY_TOKEN=true`，并同步关闭包含查询串的访问日志。
- Webhook 文件日志默认 20 MB 轮转，保留 5 份，可通过环境变量调整。
- 浏览器真实数据访问仍需 P2 正式登录和后端会话鉴权。本轮不把内部密钥下发到前端，也不把真实接口改成公开接口。
