# P2 认证会话与安全运行说明

## 1. 会话机制

- 密码使用 bcrypt 哈希，默认工作因子 12。
- 登录成功后生成 32 字节随机会话令牌和独立 CSRF 令牌。
- MySQL 只保存令牌 SHA-256 摘要，不保存原始令牌。
- 会话 Cookie 为 `HttpOnly; Secure; SameSite=Lax; Path=/`。
- CSRF Cookie 可由同域前端读取，仅用于非 GET 请求的双提交校验。
- 默认空闲有效期 2 小时，绝对最长 12 小时。
- 退出、账号禁用和密码重置立即撤销相关会话。

## 2. 登录保护

- 登录账号统一转为小写并去除首尾空格。
- 不存在的账号也执行一次固定 bcrypt 校验，避免明显账号枚举时差。
- 登录失败使用统一文案，并增加固定延迟。
- 单账号连续失败默认 5 次后锁定 15 分钟。
- 单 IP 默认 15 分钟内最多 10 次登录尝试。
- 政府端、诊断接口默认每 IP 每分钟最多 600 次。
- Webhook 默认每 IP 每分钟最多 300 次，超限请求只写脱敏拒绝日志，不进入 JSONL/MySQL。

## 3. 来源与浏览器安全

- 生产允许来源仅为 `https://axsztech.cn` 和 `https://www.axsztech.cn`。
- CORS 不返回通配符，并允许同域凭据。
- 登录、退出和下载校验可信来源。
- 下载必须同时通过服务端会话、项目权限、下载权限和 CSRF。
- API 返回 `no-store`，并设置 `nosniff`、CSP、Referrer Policy、Frame 和 Permissions Policy。
- 服务端错误不回显 SQL、密码、Cookie、内部密钥或完整连接串。

## 4. 环境变量

新增配置均位于服务器受保护环境文件中，示例只保留空值或安全默认值：

```text
AUTH_COOKIE_NAME
AUTH_CSRF_COOKIE_NAME
AUTH_COOKIE_SECURE
AUTH_TRUSTED_ORIGINS
AUTH_SESSION_IDLE_MINUTES
AUTH_SESSION_MAX_HOURS
AUTH_BCRYPT_ROUNDS
AUTH_LOGIN_MAX_ATTEMPTS
AUTH_LOGIN_LOCK_MINUTES
AUTH_LOGIN_RATE_LIMIT
AUTH_API_RATE_LIMIT_PER_MINUTE
WEBHOOK_RATE_LIMIT_PER_MINUTE
REPORT_PDF_FONT_PATH
```

## 5. 运行边界

- `/gov/pingxiang-demo` 为公开演示入口，只读前端演示数据，不调用真实 API。
- `/gov/pingxiang` 为正式入口，必须登录并绑定 `pingxiang` 项目，固定读取 MySQL 真实数据。
- 正式数据归集失败时显示暂无数据或归集异常，不回填演示数字。
- `/api/caoliao/health` 保持公开且只返回健康状态。
- 草料原始事件诊断接口不向项目查看账号开放；管理员也只获得裁剪后的诊断摘要。
