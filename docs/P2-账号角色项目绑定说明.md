# P2 账号、角色与项目绑定说明

## 1. 最小角色模型

P2 只保留两类服务端角色：

| 角色 | 使用主体 | 能力 |
| --- | --- | --- |
| `admin` | 安巡内部管理员 | 查看绑定项目数据、访问受限诊断摘要、下载汇总和授权范围内明细 |
| `project_viewer` | 平乡县应急管理局、平乡人保 | 只读绑定项目，允许汇总报告和汇总 Excel，默认禁止企业原始明细下载 |

应急局和人保使用不同账号，通过 `organization_name`、`organization_type` 和审计日志区分，不额外创造角色。

## 2. 数据范围

账号通过 `auth_user_projects` 与 P1 的 `projects` 绑定。县域由 `projects.county_id` 间接确定，企业和记录必须继续通过 P1 的 `project_id/company_id` 关系校验。

浏览器传入的 `projectId`、`countySlug`、`companyId` 和 `recordId` 只用于定位资源，不能作为授权依据。平乡接口先从服务端会话读取用户，再检查其 `pingxiang` 项目绑定，最后执行带 `project_id` 和数据环境条件的数据库查询。

## 3. 账号创建与禁用

首批账号使用受控 CLI 管理，不开发账号管理 UI：

```text
npm run auth:user -- --action create --username <用户名> --display-name <显示名> --organization <机构> --organization-type <anxun|government|insurer> --role <admin|project_viewer> --project pingxiang
```

密码只能通过标准输入或临时环境变量 `P2_ACCOUNT_PASSWORD` 提供，必须同时包含大小写字母、数字和特殊字符且不少于 12 位。脚本不输出密码和密码哈希。

禁用与启用：

```text
npm run auth:user -- --action disable --username <用户名>
npm run auth:user -- --action enable --username <用户名>
```

禁用账号或重置密码会撤销现有会话，并写入认证审计日志。

## 4. 首批账号交付原则

- 安巡、应急局、人保使用三个独立账号。
- 正式密码不写入 Git、任务报告、普通日志或聊天记录。
- 账号交接文件只能存放在服务器 root 可读目录，权限设为 `600`。
- 交接完成后由负责人通过独立安全渠道取得初始密码。
- P2 不实现企业账号、自由权限配置、密码找回、短信、MFA 或 SSO。
