# P2 上线与回退运行手册

## 上线前

1. 确认功能分支基于最新 `origin/main`，无强制推送。
2. 完成 `npm ci`、服务端测试、TypeScript、生产构建和浏览器自动化回归。
3. 检查仓库中不存在密码、AccessKey、会话令牌、Webhook 密钥或完整数据库连接串。
4. 为当前生产提交创建并推送 P2 上线前回退标签。
5. 执行 RDS 完整备份并记录当前 `schema_migrations`。
6. 确认服务器受保护环境文件权限为仅管理员可读。

## 部署顺序

1. 安全合并 P2 功能分支至最新 `main`。
2. 由现有 `Deploy Main` 工作流构建并同步前端静态文件与服务端目录。
3. 远端发布脚本使用维护账号执行 `005_p2_auth_foundation` 迁移。
4. 远端服务继续以 `anxun_runtime` 连接 MySQL，运行账号只获得 P2 认证、会话和审计表所需最小权限。
5. 创建安巡、应急局和人保三个独立账号，并分别绑定 `pingxiang` 项目。
6. 将正式入口数据源设为 MySQL，公开演示入口保持固定演示数据。
7. 通过 PM2 重载 `anxun-caoliao-webhook`，不得改变 P1 四类 Webhook 识别与入库逻辑。

## 上线验证

- 官网、中台和 `/gov/pingxiang-demo` 正常访问。
- `/gov/pingxiang` 未登录跳转至正式登录页。
- 匿名正式 API 返回 401。
- 三个正式账号分别登录成功并恢复会话。
- 应急局和人保只能读取平乡项目，不能下载企业记录明细或访问草料诊断接口。
- 安巡管理员只能在绑定项目范围内读取数据，可按授权下载明细。
- 阶段报告 PDF、企业运行汇总和四项业务汇总可下载并产生区分机构的审计日志。
- 禁用临时验收账号后，旧会话立即失效。
- Webhook 正确密钥、错误密钥、重复请求和四类真实 RDS 入库回归通过。

## 回退

1. 将前端和服务端恢复到 P2 上线前回退标签对应提交。
2. 保持 `/gov/pingxiang-demo` 可用，正式 `/gov/pingxiang` 不得回退为匿名真实数据。
3. 如需回退数据库，先禁用正式入口和认证服务，再确认 P2 表无有效会话及必须保留的审计数据。
4. 仅在明确确认后执行 `005_p2_auth_foundation.down.sql`；P1 业务表、四类记录和 Webhook 原始事件不得删除。
5. 重载 PM2 后验证匿名真实接口仍不可访问，Webhook 与公共演示页无回归。

## 账号交付

正式初始密码只通过独立安全渠道交付，不写入 Git、报告、普通日志或聊天记录。服务器临时交接文件必须位于 root 专用目录、权限为 `600`，交接完成后及时清理。
